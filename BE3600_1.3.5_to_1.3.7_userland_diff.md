# Archer BE3600/BE230 V2.6 — userland diff, 1.3.5 → 1.3.7

Decompiled-source comparison of the two decrypted OEM images. Scope: the SquashFS
root filesystem. Goal: decompose the single-line "Improved overall security"
changelog into provable changes.

## Images
| | version | build | squashfs @ | inodes |
|---|---|---|---|---|
| A | 1.3.5 | 20260812 rel.8951 | 0x5C4085 | 4994 |
| B | 1.3.7 | 20261022 rel.15717 | 0x5C34DA | 4995 |

Both: TP-Link "Cloud" wrapper header → U-Boot 2019.07 → FIT (kernel + per-board
DTBs for BE220 / BE230V2 / BE3600ProJP) → SquashFS 4.0 / xz rootfs.

## Method
1. `unsquashfs` both rootfs (standard xz; nothing exotic).
2. Tree diff by sha256: **1 added, 0 removed, 499 changed**.
3. Recovered TP-Link's shuffled Lua 5.1 opcode order from the device's own
   `liblua.so.5.1.4` (`tplink_lua_opmap.py from-lib`) — **identical order in both
   builds**. Unshuffled + retargeted each changed `.lua` to canonical stock
   bytecode (`tplink_lua_unshuffle.py`), decompiled with unluac.
4. Normalized decompiler register/upvalue names before diffing, because unluac's
   local-slot renumbering inflates raw diffs by ~20–600×.

## Signal vs noise
- **391 / 499** changed files are `opkg/info/*.control` manifests differing only in
  `Installed-Size` byte counts — pure recompilation metadata.
- **26** `.so` + assorted binaries recompiled.
- `access_control.lua` and `device_config.lua`: bytecode changed, **decompiled
  source identical** → compiler noise.
- `dispatcher.lua`: raw 1382-line diff → **2 real lines** (an error-500 string);
  renumbering cascade accounted for the rest.

## Genuine security fixes NOT spelled out in the changelog
The coherent theme of 1.3.7's "security" work: a sweep replacing
`os.execute()`-with-string-interpolation by argv-array `subprocess.exec` (no
shell → no injection), and moving secrets/data into `chmod 600` temp files.

1. **VPN credential exposure (vpn.lua).** 1.3.5 passed PureVPN creds inline on the
   curl command line (`--data-raw '{"client_id":"%s","username":"%s","password":"%s"}'`)
   — visible in `ps`, injectable. 1.3.7 writes them to
   `/tmp/thirdvpn_purevpn_login.data`, `chmod 600`, uses `curl --data @file`, then
   `os.remove`s it. Input validation tightened from `safestring` to a new
   `alphanumeric_str` (charset `[A-Za-z0-9]` + `-_`).
2. **Weather command injection (weather_controller.lua).** Same pattern:
   `os.execute("ubus send weather_settings_update '" .. json.encode(x) .. "'")`
   became `subprocess.exec({"ubus","send","weather_settings_update", json.encode(x)})`.
   City-search data now written to `/tmp/city_search_http_data` with `chmod 600`.
3. **SMB share path traversal (folder_sharing.lua).** Added `realpath`-based
   containment: the real share path must sit under the real mount dir, else
   "Invalid sharename". Blocks a share escaping its volume.
4. **New strict validator (datatypes.lua).** `alphanumeric_str(s, extra)` —
   per-char allowlist; backs fix #1.

## Dropbear: NOT a version bump (correcting the changelog read)
Binary changed (sha differs, in the changed list) but the banner is identical in
both: `SSH-2.0-dropbear_2019.78`. ELF delta is tiny — `.text` +0x28, `.rodata`
+0x30, identical 187-entry dynsym (no new imports). radiff2 shows ~97–99%
similarity across nearly every function = recompile + small insert (literal-pool
address drift), not a broad rewrite.

The real change is one TP-Link-local function (`fcn.0x2a968`) — an SSH
algorithm-compatibility shim gated on `/tmp/ssh_algo_version` (present in BOTH
builds). What 1.3.7 adds:
- a **third algorithm class: host keys** (`ssh-rsa,ssh-dss` default / `ssh-rsa`
  legacy-branch) — 1.3.5 only toggled KEX and MAC;
- `kexguess2@matt.ucc.asn.au` appended to the KEX list;
- a standalone `diffie-hellman-group14-sha1` for the legacy branch.

Security read: this is **compatibility, not hardening** — it manages (and by
default advertises) legacy/weak algorithms (SHA-1 KEX, hmac-md4/md5, ssh-dss).
Minor downgrade-surface note: the policy is read from a predictable `/tmp` path at
startup; a local process able to write `/tmp/ssh_algo_version` first can influence
the advertised set.

## CA cert lifecycle — end to end (`/etc/init.d/uhttpd`, 1.3.7)
No `cacert.pem` is baked into the rootfs; it is generated/persisted at runtime.
Full flow:

1. **Load from flash:** `nvrammanager -r /tmp/https_cert.cry -p https_cert` pulls the
   persisted bundle; if `trk_enc_file` is on it is AES-256-CBC + zlib
   (key/iv from `libtrkutil crypto.lua.key`/`.iv`), else a plain tar. Unpacks to
   `/tmp/{uhttpd.crt,uhttpd.key,cacert.pem}`.
2. **Completeness gate (the 1.3.7 change):** regen trigger now also fires if
   `/tmp/cacert.pem` is missing — so the CA is kept in sync with the host cert,
   not just the host key/cert pair.
3. **Generate (`generate_keys`):**
   - self-signed **CA**: `openssl req -x509 … -keyout demoCA/private/cakey.pem
     -out cacert.pem -subj /CN=$commonname -days 3650` → **10-year CA** ✓
   - host key + CSR, then `openssl ca … -startdate 200101000000Z
     -enddate 401231000000Z` → host leaf fixed 2020→2040 ("to fix Chrome/MacOS").
   - `cp demoCA/cacert.pem /etc` → **persists the CA public cert** ✓
   - `rm -rf /etc/ssl/demoCA` → **destroys the CA private key** (`cakey.pem` lived
     only here; never persisted, never downloadable).
4. **Re-persist:** `tar -czf … uhttpd.crt uhttpd.key cacert.pem` — 1.3.7 adds
   `cacert.pem` to the tar (1.3.5 stored only crt+key) → optional AES+zlib →
   `nvrammanager -w … -p https_cert`. **This is what makes the CA survive reboots.**
5. **Download:** `cert_mgmt.lua` does `cat /etc/cacert.pem` → serves the CA
   **public** cert only. Install it as a trusted root and the router's HTTPS UI
   validates without a browser warning.

Net: "downloadable router CA cert + persisted 10-year CA chain" = the
`cert_mgmt.lua` endpoint (download) + `cacert.pem` added to the nvram `https_cert`
bundle (persistence) + the `-days 3650` self-signed CA that signs the 2020–2040
host leaf (10-year chain). Chain lifetime is bounded by the CA's 10 years. Private
key hygiene is sound — only the public cert leaves the box.

## Reusable pipeline
`liblua.so → tplink_lua_opmap.py from-lib → tp_opnames.txt`, then per file:
`tplink_lua_unshuffle.py --opnames tp_opnames.txt in.luac out.luac → unluac`.
Opcode order is stable across 1.3.5/1.3.7, so the opmap is reusable for future
builds until TP-Link reshuffles.
